The pipes — what happens without you

Five flows, left to right. Click any hop for its full detail (panel at the foot). Green hops keep running in a token outage; amber hops stop; violet is you.

1 · A renter texts SMS · survives outage until the reply step

Without you: emergencies summon staff and simple questions get answered even in a full token outage. A judgment reply is drafted within ~30 min but nothing sends until a human releases it.

2 · An email arrives business Gmail · the weakest inbound pipe
Business Gmail→ gmail_pull ledger→ Concierge 2-hourly triage→ Notion tickets

Without you: mail is archived deterministically, but nothing acts on it until an LLM pass — up to ~2h daytime, ~10h overnight. No emergency regex watches this pipe (fix-list item 3). The ledger cron rides flaky GitHub Actions.

3 · A message goes out every outbound email/SMS · human-gated by design
agent drafts a queue row→ Pending Review · you release→ send engine 1-min poll · v18 guards→ renter

Without you: nothing customer-facing sends — your release is the valve. The engine refuses malformed rows instead of sending them (single sender identity, Invariant J unthreaded-reply guard); failures flip to Error + alert email, never silent. Scheduled FBS sends (HTA/EOB/AVA) flow once queued.

4 · A booking becomes access Skedda → alarm codes · ⚠ upstream data is broken
Skedda ⚠ cookie→ fbs-monitor 15-min rebuild→ Doorman 04:00 + ~06:00→ PIN digits — staff→ HTA with code

Without you: the board rebuilds and the Doorman preflights access 7 days out, checks arm state overnight, and proposes (never executes) code retirements. PIN digits stay human — the panel masks them. Everything here reads through the broken Skedda cookie (fix-list item 1) until it is reseeded.

5 · Something breaks watchers watching workers · deterministic where it counts
fbs-watch 15-min→ Slack #desk-status Sentinel + Watchman hourly→ miss → SMS desk-loop + invariants→ alarm-watchdog DRY RUN→ watchdog log overnight reports→ your morning surfaces

Without you: a fleet outage reaches Slack deterministically; a missed agent run reaches your phone. The alarm watchdog only logs what it would do (fix-list item 4). Everything else lands on the Night Watch / Fixer pages for your morning.

    Job D can now fix what it finds — and the board grew a Reports tab to say soCHANGE

    The daily code check could detect drift but never repair it, by construction. /code-match answers match/differs/unknown and deliberately never returns a digit, which is what lets the unattended cloud Doorman run it without a PIN entering an agent transcript. The cost of that guarantee: a differs was unfixable by the thing that found it, so every correction waited on an attended local session. New route POST /code-mirror on alarm-mcp closes it from the other side — that service already holds the Alarm.com credential, so it reads the code, writes it into the Artist DB, and drops it, returning counts and names only. Both routes judge through one shared code_sweep.sweep(), so the verdict-only and correcting surfaces cannot drift apart; a single strip_codes() call is what separates them.

    It acts on one state and counts the rest. Both sides hold a code and they differ — that is the state that texts somebody a PIN which will not open the door. “No panel user” is normal and is never a finding (owner ruling 2026-08-14): the Artist DB keeps a code after the panel user is retired so a returning renter gets the number they already remember, and 534 of 696 rows are in exactly that state. An earlier build reported all 534 as findings, which is a 534-line report nobody reads. Two states that no machine can resolve — one name matching two panel users, and panels disagreeing with each other — go to a human, and nothing ever blanks a populated field, because an empty Alarm Code sends an HTA with a hole in it.

    A real bug fell out of the port. judge_claims called find_codes once per claim, and find_codes walks the entire paginated Alarm.com roster — so the 696-name sweep /code-match was built for meant 696 roster walks, several thousand requests. It was never noticed because the route had only ever been called with a handful of claims. The roster is now fetched once and deviceAccess memoised per user id; matching semantics are unchanged.

    Scheduling: a new alarm-code-mirror Cloud Scheduler job, daily 04:30, hitting the route directly — the same shape as the two alarm-watchdog jobs. The tab reads titles only, never bodies: titles are written to be published, bodies carry renter names, and that board is a public GitHub Pages site. The row stays on the board and stays counted in the flag total; only the colour and the claim change.
